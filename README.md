# 🔎 RepoInsight

أداة ويب تحلّل **المستودعات العامة لأي حساب GitHub** وتقيّم جودتها: إحصائيات، رسوم بيانية، فحص لكل مستودع، توصيات بما يجب إصلاحه أولًا، وتقارير قابلة للتنزيل.

> أدخل اسم المستخدم (مثل `torvalds`) وستحصل على لوحة تحليل كاملة خلال ثوانٍ.

---

## ✨ المميزات

### الإحصائيات والرسوم
- عدد المستودعات العامة، إجمالي ⭐ Stars وForks، وعدد اللغات.
- توزيع المشاريع حسب اللغة (Pie)، وأكثر المشاريع Stars وForks (Bar).
- المستودعات المنشأة في كل سنة، وأكثر Topics استخدامًا.
- المشاريع المتوقفة (لم تُحدَّث منذ أكثر من سنة).
- جدول لكل مستودع: بحث بالاسم، ترتيب بأي عمود، إخفاء الـ Forks، عرض النواقص فقط.

### فحص جودة كل مستودع
| الفحص | كيف يُكتشف |
|---|---|
| README | ملف `README*` في جذر المستودع |
| محتوى README | حجمه 500 بايت فأكثر |
| وصف واضح | 20 حرفًا فأكثر |
| LICENSE | ملف ترخيص، أو ترخيص مسجَّل في GitHub |
| الاختبارات | مجلدات `test/` `tests/` `__tests__/` `spec/`، أو ملفات `*.test.js` `*.spec.ts` `test_*.py` `*_test.go` … |
| CI | `.github/workflows/*.yml` أو GitLab CI أو Travis أو CircleCI أو Jenkinsfile |
| `.gitignore` | موجود في الجذر |
| Topics | مستودع له Topic واحد على الأقل |
| النشاط | آخر Push خلال 180 يومًا (نصف النقاط حتى سنة) |

### درجة الاكتمال (من 100) والتقدير
| المعيار | النقاط |
|---|---|
| README | 20 |
| الاختبارات | 15 |
| النشاط | 13 |
| الوصف | 12 |
| LICENSE | 12 |
| CI | 10 |
| Topics | 8 |
| محتوى README | 5 |
| `.gitignore` | 5 |

التقدير: **A** ≥ 90 · **B** ≥ 75 · **C** ≥ 60 · **D** ≥ 40 · **F** أقل من ذلك.

- الـ **Forks** لا تُقيَّم لأنها ليست من عملك.
- المستودعات **المؤرشفة** لا تُعاقَب على قلة النشاط.
- اضغط على أي صف في الجدول لرؤية تفصيل النقاط ونصائح التحسين لهذا المستودع.

### أدوات إضافية
- 🛠 **ما الذي تُصلحه أولًا؟** قائمة مرتبة حسب عدد النقاط التي ستكسبها لو أصلحت كل معيار.
- ⚖️ **مقارنة حسابين** جنبًا إلى جنب مع رسم Radar.
- ⬇ **تقارير قابلة للتنزيل:** Markdown، HTML (قابل للطباعة كـ PDF)، CSV (يفتح في Excel بالعربية)، JSON.
- 🏷 **شارة SVG** لوضعها في README الخاص بك (انظر أدناه).
- 🌙 وضع داكن، 🔗 رابط مباشر `?user=اسم`، وحفظ آخر عمليات البحث.

## 🚀 التشغيل

المتطلبات: **Node.js 20.12 أو أحدث**.

```bash
# 1) تثبيت كل الحزم
npm run install:all

# 2) (موصى به) ضع توكن GitHub
cp .env.example .env
#   ثم عدّل GITHUB_TOKEN داخل .env

# 3) تشغيل وضع التطوير
npm run dev
```

- الواجهة: http://localhost:5173
- الخادم: http://localhost:4000

### وضع الإنتاج
```bash
npm run build
npm start          # يخدم الواجهة والـ API معًا على http://localhost:4000
```

### Docker
```bash
GITHUB_TOKEN=ghp_xxx docker compose up --build
```

### لماذا أحتاج توكن؟
بدون توكن حد GitHub هو **60 طلبًا في الساعة**، والتحليل العميق يستهلك طلبًا لكل مستودع مفحوص بالإضافة إلى طلبات الحساب؛ لذلك يُعد التوكن عمليًا للاستخدام المتكرر أو للحسابات الكبيرة (يظهر العدد المتبقي في الواجهة). مع التوكن يصبح الحد **5000**.
أنشئ توكنًا من https://github.com/settings/tokens **بدون أي صلاحيات (scopes)**؛ فهو يكفي لقراءة البيانات العامة.

## 🔌 واجهة الـ API

| المسار | الوصف |
|---|---|
| `GET /api/analyze/:username?max=30` | تحليل كامل بصيغة JSON. `max` عدد المستودعات التي يُفحص محتواها (5–60). |
| `GET /api/history/:username` | لقطات متوسط الدرجة المخزنة لهذا الحساب خلال آخر 90 يومًا. |
| `GET /api/badge/:username.svg` | شارة SVG بمتوسط الاكتمال. |
| `GET /api/health` | حالة الخادم. |

النتائج تُخزَّن مؤقتًا 10 دقائق بذاكرة محدودة، وتُدمج الطلبات المتزامنة للتحليل نفسه لتقليل استهلاك GitHub API. تُحفظ في SQLite لقطة مختصرة من كل تحليل جديد (متوسط الدرجة وعدد المستودعات فقط)، وتُحذف اللقطات الأقدم من 90 يومًا. ملف قاعدة البيانات الافتراضي `server/data/repo-insight.sqlite`، ويمكن تغييره عبر `HISTORY_DB_PATH`.

### إعدادات الأمان
- تُرسل الواجهة ترويسات حماية للمتصفح، ولا يُسمح بطلبات CORS من مواقع خارجية افتراضيًا. للسماح بموقع موثوق، أضف أصوله الدقيقة مفصولة بفواصل إلى `CORS_ALLOWED_ORIGINS` (مثل `https://example.com`)، دون مسارات.
- لكل عنوان IP حد طلبات منفصل؛ حد التحليل 40 طلبًا لكل 10 دقائق، مع حد عالمي لعشرة تحليلات متزامنة. الذاكرة المستخدمة لتتبع العناوين محدودة.
- اتصالات GitHub لها مهلة 15 ثانية. لا تكشف استجابة فحص الصحة عن وجود توكن GitHub أو إعدادات البروكسي.

### النشر خلف Proxy
حد الطلبات يعتمد على عنوان IP الذي يراه Express. القيمة الافتراضية `TRUST_PROXY_HOPS=0` لا تثق بأي Proxy. إذا كان كل المرور يصل عبر Proxy موثوق واحد، اضبط `TRUST_PROXY_HOPS=1`؛ استخدم عدد القفزات الفعلي فقط إذا كانت كل المسارات إلى الخادم تمر بالبنية نفسها، ولا تفعّل الثقة العمياء بالقيمة `true`.

في Docker Compose تُحفظ قاعدة البيانات في volume دائم. عند النشر على منصة أخرى، اربط قرصًا دائمًا بمسار قاعدة البيانات أو عيّن `HISTORY_DB_PATH` إلى موقع دائم؛ وإلا سيضيع سجل الاتجاه عند إعادة إنشاء الحاوية.

### الشارة
بعد نشر المشروع على خادم، ضع هذا في README حسابك:
```markdown
![repo health](https://YOUR-HOST/api/badge/YOUR-USERNAME.svg)
```
وزر «نسخ شارة README» في الواجهة يجهّز السطر لك.

## ⚠️ ملاحظات وحدود المؤشر
- درجة الاكتمال **مؤشر إرشادي** يستند إلى وجود ملفات وبيانات عامة قابلة للتحقق، وليست حكمًا على جودة الكود أو الاختبارات أو ملاءمة كل معيار لنوع المشروع. تُطبَّع الدرجة على المعايير المعروفة فقط؛ المعايير غير المعروفة لا تُحسب كنواقص، وتظهر نسبة التغطية لكل مستودع.
- GitHub قد يقتطع شجرة ملفات المستودعات الكبيرة؛ عندها تظهر الفحوصات التي لم يمكن التحقق منها كـ «غير معروف»، ويظهر تنبيه في التقرير.
- يُحلَّل أحدث المستودعات نشاطًا أولًا حتى الحد الذي تختاره (15 / 30 / 60)، وتظهر رسالة إن تم تقييد الفحص.
- المستودعات الفارغة تُعامَل كأنها بلا أي ملفات. وإن تعذّرت قراءة شجرة ملفات مستودع فتُعرض معاييره كـ «غير معروف» ولا تُحتسب كإخفاق.
- المشروع يقرأ **البيانات العامة فقط**، ولا يحتاج أي صلاحية على حسابك.
